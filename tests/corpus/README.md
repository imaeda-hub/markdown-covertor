# 検体（テストに使う実資料）

実際の資料で変換を試し、**通ったものと通らなかったものを分けて残す**場所。
「動くことの確認」で終わらせず、**壊れている実例を消さずに置いておく**のが目的。

## 3 つのフォルダ

```
inbox/    ←  あなたがここに資料を置く（未検査）
   │
   ↓  毎晩のループが変換して判定
   │
   ├─→ passing/   通った。変換後の Markdown と要約を置き、以後の退行を検出する
   │     ├ converted/   ← 変換結果そのもの（画像つき）。実物を読める
   │     └ expected/    ← 要約（構造・警告・ハッシュ）
   │
   └─→ failing/   通らなかった。症状レポートと「現在の壊れ方」を残す
         └ expected/    ← 壊れ方の要約（静かな悪化を検出する）
```

**`failing/` の資料は、成功するまで毎回のループでテストされ続ける。**
1 回失敗して終わりではなく、ループが回るたびに再変換される。
直ったら `passing/` に昇格し、症状レポートは消え、
変換結果が `converted/` に置かれ、journal に「何が直ったか」が記録される。

## あなたがやること

`tests/corpus/inbox/` にファイルを置いて push するだけです。あとはループが処理します。

- **ファイル名は自由**。日本語でも構いません
- 対応形式は `.docx` / `.xlsx` / `.pptx` / `.pdf`
- **公開して困る資料は置かないでください。** リポジトリに残り、履歴からも消えません
- 目安は 1 ファイル 5MB 程度まで（大きすぎるとリポジトリが重くなります）

## 通った / 通らなかった の判定基準

**通った（passing）**

- 例外を出さずに変換できる
- **文字情報が失われていない**（本文・表の中身・箇条書きが出ている）
- 見出し・表・リストの構造が保たれている
- 落ちるのは Markdown に表現できない要素（画像・グラフ・図形）だけで、
  それらは**警告として報告されている**

**通らなかった（failing）**

- 例外が出る、または出力が空になる
- 本文の文字が欠落する、単語が壊れる
- 表が段落に潰れる、段組みで順序が乱れるなど、構造が明確に壊れる
- 情報が落ちているのに警告が出ない

判定に迷うものは `failing/` に置く。**疑わしきは失敗**として扱う。

## 何が保存されるか

| 場所 | 中身 | 何のため |
|---|---|---|
| `passing/converted/<元の名前>.md` | **変換後の Markdown 全文**（画像は同階層の `assets/`） | 実際にどう変換されるかを人間が読める |
| `passing/expected/<元の名前>.summary.md` | 構造の要約・警告一覧・SHA256 | 大きい資料でも差分の意味が読み取れる |
| `failing/<元の名前>.md` | 症状 / 原因 / 期待する出力 / タスク | なぜ通らないのかを説明する |
| `failing/expected/<元の名前>.summary.md` | **現在の壊れ方**の要約 | 直っていないものが静かに悪化するのを防ぐ |

変換後ファイルの名前に拡張子を残している（`test.docx.md`）のは、
`test.docx` と `test.xlsx` のように**同名で形式違いの検体**が衝突しないようにするため。

出力が変わると（良くなったときも）テストが落ちる。それが**差分として見える**のが狙い。

更新は `UPDATE_GOLDEN=1 .venv/bin/pytest tests/test_corpus.py`。
**差分を必ず目で確認すること。** 更新は「仕様が変わった」という宣言になる。
