# 検体（テストに使う実資料）

実際の資料で変換を試し、**通ったものと通らなかったものを分けて残す**場所。
「動くことの確認」で終わらせず、**壊れている実例を消さずに置いておく**のが目的。

## 3 つのフォルダ

```
inbox/    ←  あなたがここに資料を置く（未検査）
   │
   ↓  毎晩のループが変換して判定
   │
   ├─→ passing/   通った。変換結果の要約を固定し、以後の退行を検出する
   └─→ failing/   通らなかった。症状レポートを添えて残し、毎回再挑戦する
```

`failing/` の資料は**毎回のループで再変換**され、直ったら `passing/` に昇格する。
昇格したらレポートは消え、journal に「何が直ったか」が記録される。

## あなたがやること

`tests/corpus/inbox/` にファイルを置いて push するだけです。あとはループが処理します。

- **ファイル名は自由**。日本語でも構いません
- 対応形式は `.docx` / `.xlsx` / `.pptx` / `.pdf`
- **公開して困る資料は置かないでください。** リポジトリに残り、履歴からも消えません
- 目安は 1 ファイル 5MB 程度まで（大きすぎるとリポジトリが重くなります）

## 通った / 通らなかった の判定基準

**通った（passing）**

- 例外を出さずに変換できる
- **文字情報が失われていない**（本文・表の中身・箇条書きが出ている）
- 見出し・表・リストの構造が保たれている
- 落ちるのは Markdown に表現できない要素（画像・グラフ・図形）だけで、
  それらは**警告として報告されている**

**通らなかった（failing）**

- 例外が出る、または出力が空になる
- 本文の文字が欠落する、単語が壊れる
- 表が段落に潰れる、段組みで順序が乱れるなど、構造が明確に壊れる
- 情報が落ちているのに警告が出ない

判定に迷うものは `failing/` に置く。**疑わしきは失敗**として扱う。

## 期待値の持ち方

`passing/expected/` と `failing/expected/` に変換結果の要約を固定している。
**通らなかった資料も固定する。** 直っていないものを放置すると、
静かに悪化しても気づけないため。良くなったときもテストが落ち、差分として見える。

- **SHA256** で全文の完全一致を担保（1 文字変われば落ちる）
- **要約**（見出し一覧・表の形・警告一覧）で、落ちたときに何が変わったか読んで分かる

更新は `UPDATE_GOLDEN=1 .venv/bin/pytest tests/test_corpus.py`。
**差分を必ず目で確認すること。** 更新は「仕様が変わった」という宣言になる。
