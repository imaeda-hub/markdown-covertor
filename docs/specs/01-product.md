# プロダクト仕様

> **一言でいうと**
> Word / Excel / PowerPoint / PDF の資料を、読みやすい Markdown に変換するツール。

| 項目 | 内容 |
|---|---|
| 名前 | `mdconv` |
| 現在のバージョン | 0.1.0（MVP） |
| 提供形態 | CLI（現在） → GUI（将来） |
| 動作条件 | Python 3.10 以上。インターネット接続不要 |
| 最終更新 | 2026-08-15 |

## 1. なぜ作るか

社内資料は Office 形式と PDF に閉じ込められている。そのままでは

- Git で差分が見えない
- 検索・grep が効かない
- AI（RAG・要約）に食わせにくい
- 内容の再利用にコピペが要る

Markdown にしてしまえば、これらがすべて解決する。
**「資料の中身をテキストとして扱えるようにする」**のがこのツールの役割。

## 2. 誰が使うか

| 利用者 | 使い方 | いちばん困ること |
|---|---|---|
| 資料を整理したい人 | 手元の資料をまとめて変換 | 大量のファイルを 1 つずつ開くのが面倒 |
| ドキュメントを Git 管理したい人 | 変換して commit | 変換のたびに差分が暴れると困る |
| AI に資料を読ませたい人 | 変換して RAG に投入 | 表や見出しが壊れると精度が落ちる |

## 3. 大事にすること（優先順位つき）

判断に迷ったときは、この順で上を優先する。

1. **情報を失わない** — 変換で消える情報があるなら、黙って消さず警告として伝える
2. **構造を保つ** — 見出し・表・箇条書きは、見た目より「構造」を優先して復元する
3. **すぐ動く** — 巨大なモデルのダウンロードや GPU を前提にしない
4. **手元で完結する** — 既定では外部にファイルを送らない（社内資料を扱うため）
5. **結果が安定する** — 同じ入力からは常に同じ出力（Git 差分が意味を持つように）

## 4. スコープ

### やること

- 4 形式（.docx / .xlsx / .pptx / .pdf）から Markdown への変換
- 1 ファイル変換とディレクトリ一括変換
- 変換で落ちた情報（画像・書式など）の報告
- ライブラリとしての利用（GUI や他ツールから呼べる形）

### やらないこと（現時点）

| やらないこと | 理由 |
|---|---|
| Markdown → Office への逆変換 | 需要が別物。必要になったら別ツールとして切り出す |
| 旧バイナリ形式（.doc / .xls / .ppt） | 仕様が別物で実装コストが高い。Office での再保存を案内する |
| レイアウトの完全再現 | Markdown に表現力がない。構造の保存を優先する |
| クラウドへの自動アップロード | 社内資料を扱う前提のため |
| 既定での外部 API 利用 | 同上。使う場合は利用者が明示的に有効化する（未実装） |

## 5. 将来の方向（決定ではなく候補）

| 時期 | 候補 | 判断材料 |
|---|---|---|
| 次 | GUI（ドラッグ&ドロップで変換） | CLI が安定したら着手 |
| 次 | 高精度 PDF エンジンのプラグイン対応 | スキャン PDF の変換要求が出たら |
| 未定 | 画像の説明文を LLM で生成 | オプトイン前提。利用者の許可設定とセットで |
| 未定 | MCP サーバとして公開 | AI エージェントから直接使いたくなったら |
