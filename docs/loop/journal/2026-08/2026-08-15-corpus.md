# 2026-08-15 のループ（手動実行：検体フォルダの導入）

依頼:
1. テストに使った資料を、通ったもの／通らなかったもので分けて残す
2. 人間が置いた資料をループのテスト対象にする（inbox → passing / failing）

## やったこと

`tests/corpus/` を新設し、3 フォルダ構成にした。

```
inbox/    ← 人間が置く（未検査）
   ↓  ループが変換して判定
   ├─→ passing/   通った。要約を固定して退行を検出
   └─→ failing/   通らなかった。症状レポート + 壊れ方の要約を添えて残す
```

既存の実資料 6 件を判定基準に従って振り分けた。

| 検体 | 判定 | 理由 |
|---|---|---|
| test.docx | ✅ passing | 本文・見出し・表・箇条書きがすべて出る |
| test.xlsx | ✅ passing | 同上 |
| test.pptx | ✅ passing | 本文は出る。グラフ・画像は出せないが警告される |
| test.pdf | ❌ failing | **1 ページ目が丸ごと欠落**、段落が潰れる、単語が結合する |
| SPARSE-…borderless_table.pdf | ❌ failing | 罫線なしの表が 1 段落に潰れる |
| MEDRPT-…scan.pdf | ❌ failing | スキャン画像のため出力が空 |

`failing/` の 3 件には症状レポート（症状 / 原因 / 期待する出力 / タスク）を添えた。

## 判定基準（`tests/corpus/README.md` に明記）

**通った** = 例外なし・文字情報が失われない・構造が保たれる・
落ちるのは Markdown に表現できない要素だけで、それが警告されている。
**疑わしきは失敗**として扱う。

## レビュー結果

`/code-review`（high）を実行。**7 件の指摘、すべて対応済み。**
今回は「今は緑だが、運用を始めると壊れる」種類の指摘ばかりで、質が高かった。

| 指摘 | 対応 |
|---|---|
| 例外を出す検体を failing に置いた瞬間、テストが永久に赤くなる | `MdconvError` を想定内として扱うように変更 |
| `.doc` など未対応形式を検体にすると、レポートが「孤児」と判定される | 拡張子で絞らず、置かれたものはすべて検体として扱う |
| `failing/` が空になるとフォルダごと消え、クローン時に収集エラー | `.gitkeep` を追加し、フォルダ不在でも動くようにした |
| 昇格（failing→passing）した瞬間、置き場所決め打ちのテストが壊れる | 名前で検体を探す `find_sample()` を導入 |
| PDF を failing に移した結果、**PDF の退行を誰も検出しなくなっていた** | `failing/expected/` にも要約を固定（NFR-10） |
| ドキュメントに「2 本の台帳」の記述が残っていた | 「3 つの窓口」に統一 |
| journal のリンク文言が実態と合っていない | 修正 |

**5 件目が重い。** 壊れているものを failing に隔離したことで、
「壊れ方が静かに悪化しても気づけない」状態を作りかけていた。
通らなかった資料も要約を固定することで、良くなったときも悪くなったときも差分が出る。
