### 実資料が炙り出した欠陥

| 何が起きていたか | 深刻度 |
|---|---|
| pptx のグラフが**警告なしに消える** | 高（気づけない） |
| pptx のグループ図形の中の本文が**丸ごと消える** | 高（本文の欠落） |
| pptx / xlsx の画像が**警告なしに消える** | 中 |
| PDF の表が 1 段落に潰れるが**警告がない** | 高（崩れた結果が普通の文章に見える） |
| Word のテキストボックスの中身が**警告なしに消える** | 高（T-21 に登録。今回は警告のみ） |

### 期待値の持ち方

実資料は大きく、全文を貼ると人間がレビューできない。
**ハッシュ（完全一致の担保）+ 要約（見出し一覧・表の形・警告一覧）**を固定する形にした。
落ちたときに「何がどう変わったか」が読んで分かる。

## レビュー結果

`/code-review`（high）を実行。**7 件の指摘、すべて対応済み。**

| 指摘 | 対応 |
|---|---|
| Word の**表の中**のグラフが警告されない（段落単位で走査していた） | 本文全体を一度に走査する方式に変更 |
| `mc:Choice` と `mc:Fallback` を両方数え、同じグラフが 2 回警告される | Fallback を辿らないようにし、種類ごとに件数を集計 |
| グラフがある本では画像の警告が消える条件になっていた | グラフと画像を独立に数える |
| PDF テストに pypdf のスキップ条件が無く、コアのみの環境で 4 件失敗する | `importorskip` を追加 |
| 実測時間に依存する性能テストは CI で不安定、かつ NFR-05（10MB）の証拠にならない | テストを削除し、NFR-05 を「未着手」に戻した |
| 仕様書から「図形は黙って落ちる」の記述が消えていた | テキストボックス・図形の行を復活。T-21 として登録 |
| README が test.pptx に SmartArt があると書いていたが実際は無い | 記述を修正し、SmartArt 判定は合成 uri の単体テストで担保 |

**「仕様書から不利な記述が消えていた」という指摘が重い。** 対応したものを ✅ に
書き換える際、まだできていないことを巻き添えで消していた。これは仕様書の信頼性の問題。
