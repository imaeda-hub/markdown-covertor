## レビュー結果
サブエージェントに差分を独立レビューさせた（`git diff` を渡し、仕様との一致・情報欠落・
出力安定性・テストの妥当性・後方互換を確認させた）。

- **High（対応済み・ブロッカー）**: 最初の実装は「表題以外のプレースホルダーはすべて本文」
  という判定だった。markitdown はプレースホルダーの種類を区別せず shape.text を
  すべて出力するため、フッタ・日付・スライド番号のプレースホルダーが本文の候補行にも
  `pptx_list_levels()` の結果にも**同じ個数・同じ文字列**で混ざり込み、件数・中身の
  対応づけがたまたま噛み合って**フッタの文字列を箇条書きに書き換えてしまう**（`applied=True`
  で誤り書き換え）不具合を実際のフッタ配置を模した検体で再現された。
  → 表題・字幕・ヘッダ/フッタ・日付・スライド番号等を明示的に除外する
  `_NON_BODY_PLACEHOLDER_TYPES` に変更。フッタが乗ったスライドでは本物の箇条書きも
  件数が合わなくなり記号を付けられなくなる（全か無かの対応づけのため）が、**誤った
  書き換えより安全**と判断し許容。`test_pptx_footer_placeholder_is_not_bulleted` /
  `test_pptx_list_levels_excludes_non_body_placeholders` で固定した
- **Medium（対応せず・限界として明記）**: `pptx_list_levels()` は図形を XML の出現順で
  読むが、markitdown（python-pptx 経由）は画面上の位置順に並べ替えるため、authoring 順と
  表示順がずれる資料では順序が食い違うことがある。多くは中身の不一致で安全側の
  「何もしない」に倒れることを確認したが、理論上ゼロではない。位置ベースの並べ替えは
  レイアウト継承の解決が要り大掛かりになるため、今回は見送り 03-design.md 4.6 に
  既知の限界として明記した
- **Low（対応済み）**: pptx の中身比較に docx の `_normalize_list_text`（`*_\`\\` を
  無視する緩い比較）を流用していたが、markitdown は mammoth と違い pptx の段落を
  装飾なしの素のテキストで出す（bold runs でも `**` は付かないことを実測で確認）ため、
  緩める理由がなかった。前後の空白のみを無視する厳密比較に変更し、
  `test_add_pptx_bullets_uses_strict_comparison_unlike_nest_lists` で固定
- **Low（対応せず・軽微）**: 表題の判定は `type="title"/"ctrTitle"` を見ているが、
  markitdown（python-pptx の `shapes.title`）は `idx==0` で判定する。`type` を省略した
  非標準の表題プレースホルダーがあると誤って本文扱いする可能性があるが、標準的な
  PowerPoint 生成物はほぼ必ず `type` を明示するため実害は薄く、外れても中身不一致で
  安全側の「何もしない」に倒れるだけ（対応づけの穴ではなく取りこぼしのみ）。見送り
- **指摘（ドキュメントの誠実さ・対応済み）**: テキストボックスだけで書かれた箇条書きは
  `pptx_list_levels()` が空リストを返し、`api.py` は「本文プレースホルダーが無い（正常）」
  と「対応づけに失敗した（異常）」を区別できないため**警告も出ない**。05-conversion-rules.md
  と 03-design.md に明記し、「できないことを隠さない」を守った
