# AI からの質問（未回答の台帳）

AI が仕様を決められなかった点を、**回答が出るまでここに残す**場所です。

- 各質問の「**回答**」欄に一言書いてください。書き方は自由です
- 回答が出るまで、AI は**その質問に依存するタスクを実装しません**（推測で作らない）
- 一度書いた質問は、回答が出るまで**同じ質問を何度も聞き直しません**
- 回答済みの質問は「決定の記録」に移り、**なぜそう決めたかの履歴**として残ります

チャットで直接答えてもらっても構いません。その場合は AI がここへ転記します。

### Q-05 PDF の「表は復元できません」警告を、常に出してよいか

- **背景**: PDF は構造情報を持たないため表が 1 段落に潰れるが、**潰れた結果が普通の文章に見えてしまう**。
  実資料（罫線なし表の帳票）で確認したところ、表が 0 個・警告 0 件で「変換成功」に見えていた。
  そこで PDF を変換したとき必ず「表・段組みは復元できません」と伝えるようにした。
- **選択肢**:
  - A. 現状のまま（全 PDF で必ず出す）— 表がない PDF でも出るので、うるさい可能性
  - B. 表がありそうなときだけ出す — 検出方法が無いので、実質は当てずっぽうになる
  - C. 出さない — 崩れたことに気づけない
- **AI の推奨**: **A**。誤検出のない B は今の実装では作れず、C は製品原則（情報を失わない）に反する。
  ただし実際に PDF を変換して「うるさい」と感じたら変える。
- **影響**: 回答が無くても実装は進む（現状 A で動作中）。使ってみた感触を聞きたい。

### Q-06 スキャン PDF（画像だけの PDF）に対応するか

- **背景**: 紙をスキャンした PDF は文字情報を持たないため、変換すると出力が空になる。
  実例を `tests/corpus/failing/MEDRPT-…_medical_report_scan.pdf` に置いた。
  読むには OCR が要るが、これは「手元で完結する・すぐ動く」という原則と衝突する。
- **選択肢**:
  - A. 非対応と明示して終わりにする — 今の警告のまま。原則を守れる

### Q-07 markitdown で劣化した 3 項目を、補正で取り返すか

- **背景**: v0.2 で変換の本体を markitdown にした結果、次の 3 つが v0.1 より悪くなった。
  - 箇条書きの入れ子が潰れる（Word / PowerPoint）
  - Word の引用スタイルが `>` にならない
  - Word の表題が平文になる
  いずれも元ファイルを調べれば直せるが、**補正コードが増えるほど
  「markitdown に任せる」という方針から遠ざかる**。
- **選択肢**:
  - A. 3 つとも補正で取り返す（T-25/26/27）— 出力の質は戻るが、自前コードが増える
  - B. 箇条書きの入れ子だけ直す — 影響が大きいのはこれ。引用と表題は諦める
  - C. すべて markitdown の仕様として受け入れ、変換ルールに明記して終わり
- **AI の推奨**: **B**。箇条書きの階層は資料の意味に関わるが、
  引用と表題は読めれば実害が小さい。上流（markitdown）が直す可能性もある。
